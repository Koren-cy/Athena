
# 数字电子技术基础 — 笔记整理规范

## 基本原则

1. **语句通顺，表意清晰**：将口语化、碎片化的转写内容重组为流畅的书面表达。不啰嗦，不花哨。
2. **例题不可遗漏**：视频中讲解的每一道例题都必须完整收录。
3. **避免过度使用括号和破折号**：用完整的句子表达，减少插入语。
4. **标题不加编号**：如「组合电路的分析和设计方法」而非「八、组合电路的分析和设计方法」。

## 举例 vs 例题（严格区分）

### 举例

仅为说明某个概念而随手举的例子，没有明确的"问题-解答"结构。

- **重要的举例**：融入正文，不用任何 callout。作为正文的自然延续。
- **不重要的举例**：如果前面正文已解释清楚概念，举例画蛇添足——直接删除。

### 例题

有明确的已知条件 + 待求问题，需要完整解答过程。用 `[!example]` callout 呈现。

**例题的问题部分必须清晰明确**：不能只是罗列数据和现象，必须让读者知道"题目要问什么"。常见的设问形式：

- "验证……是否正确，分析原因。"
- "求……的值。"
- "用……方法实现……。"

**反面示例**（问题不明确）：
```
正五：0 101
负五：1 101
二者相加 ≠ 0。
解：问题出在...
```
→ 读者不知道要回答什么问题。

**正确写法**：
```
用原码（最高位为符号位，0正1负）表示正五和负五，验证二者相加能否归零。若不能，分析原因。
正五：0 101，负五：1 101，相加得 10010 ≠ 0。
解：不能归零。原因在于...
```

### 例题格式

```markdown
> [!example] 例：简短标题
> 完整的问题描述，包含已知条件，以明确的问句或"求/验证/分析/设计"等动词收尾。
>
> **解：** 解答过程根据视频讲解总结，步骤清晰，逻辑准确。
```

- 若有多种解法，逐一列出并标注「法一」「法二」
- 解答步骤要清晰：每一步都说明依据和理由

## Obsidian 特性使用

### Callout 类型与用途

| Callout | 用途 |
|---------|------|
| `[!abstract]` | 章节定位/概览 |
| `[!note]` | 定义、补充说明、重要举例 |
| `[!info]` | 背景信息、延伸阅读 |
| `[!tip]` | 记忆技巧、理解窍门 |
| `[!warning]` | 易错点、注意事项 |
| `[!important]` | 核心结论、必背内容 |
| `[!example]` | **例题**（仅限有明确设问和解答的解题型内容） |
| `[!danger]` | 禁止/错误做法 |

### LaTeX 数学公式

- 行内：`$Y = AB + \overline{A}B$`
- 独立行：`$$...$$`

### Mermaid 图表

- flowchart：逻辑流程、设计步骤
- state diagram：状态机、时序电路状态转移

### 表格

用于对比、归纳、分类。真值表、功能表、对照表均用 Markdown 表格。

## 内容处理要点

1. **过滤无关内容**：开场白、课程安排、考试说明等纯行政性内容不收入正文。
2. **保留知识框架**：老师强调的「本章要解决的问题」「重点」「难点」要保留。
3. **电路图描述**：用文字清晰描述电路结构和连接关系。
4. **真值表**：用 Markdown 表格呈现。
5. **卡诺图**：用表格 + 文字描述。
6. **波形图/时序图**：用文字描述波形变化，关键时间点和跳变沿。
7. **逻辑表达式**：用 LaTeX 书写。

## 文件命名

`第X讲 精简标题.md`，存放于 `7-应用与数学/数字电子技术基础/`。

示例：`第1讲 绪论与信息编码.md`

## 风格对照

| ❌ 避免 | ✅ 推荐 |
|--------|--------|
| 这个电路呢，其实它是... | 该电路通过... |
| 大家注意一下啊，这个地方... | 需要注意，此处... |
| 我们可以（通过某种方法）来实现 | 我们可以通过某种方法来实现 |
| 也就是说——它其实是一个... | 它实质上是一个... |
| 标题带编号：一、二、三、 | 标题不带编号，用层级结构自然组织 |
| 举例用 `[!example]` callout | 举例融入正文或删除，只有真正的例题才用 `[!example]` |
| 例题只罗列数据不设问 | 例题必须有明确的问句或"求/验证/分析/设计" |
