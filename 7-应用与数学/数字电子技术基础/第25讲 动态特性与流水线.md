# 时序电路的动态特性分析 第二讲

> [!abstract] 本讲定位
> 本讲分为两部分：第一部分分析同步时序电路的动态时间参数，讨论电路稳定工作的条件与最高工作频率的计算；第二部分作为补充内容，介绍流水线（Pipeline）的概念、原理及其在数字电路中的应用，通过洗衣房的类比说明流水线如何提升系统吞吐率。

## 同步时序电路的动态时间参数

在同步时序电路中，触发器的动态特性（时间参数）会直接影响到整个电路的工作性能。此前对时序电路的分析和设计一直关注稳态，从未考虑过动态问题。触发器的四个关键时间参数分为两组：一组是与组合电路相同的传输延迟参数，另一组是触发器对信号配合的要求——数据信号与触发信号之间的时序配合关系。

在同步时序电路中，所有触发器的时钟边沿是统一的，因此每个驱动方程（组合电路）的运算结果必须在时钟边沿到来之前准备好，并在时钟边沿之后保持足够长的时间。

### 电路稳定工作的两个条件

将同步时序电路抽象为若干级触发器与组合电路的串联结构，每一级都包含前级触发器、本级组合电路（驱动方程）和后级触发器。要使电路稳定工作，必须满足两个时间约束。

#### 保持时间约束

时钟边沿到达后，前级触发器输出的数据会发生变化，但后级触发器要求数据在时钟边沿之后继续保持一段时间（保持时间 $t_H$）。前级数据的保持由前级触发器的传输延迟和后级触发器的传输延迟共同保证。

由于时钟同时到达各级触发器，一旦时钟边沿到达，前级触发器输出的数据开始变化，但该数据会保持一段时间。保持时间约束要求：

$$t_{CQ} + t_{CQ} > t_H$$

其中 $t_{CQ}$ 是触发器的传输延迟。这一条件通常较容易满足，因为两个传输延迟之和一般大于保持时间。

#### 建立时间与最高工作频率

时钟边沿到达后，新数据的建立需要经过组合电路的传输延迟加上触发器的传输延迟。在两个时钟边沿的间隔（即工作周期）内，必须覆盖以下时间：

- 组合电路的最大传输延迟 $t_{PD}$（组合逻辑）
- 触发器的传输延迟 $t_{CQ}$
- 后级触发器的建立时间 $t_{SU}$

因此，最小工作周期为：

$$T_{CLK(min)} = t_{PD(max)} + t_{CQ} + t_{SU}$$

最高工作频率为：

$$f_{max} = \frac{1}{T_{CLK(min)}}$$

### 瓶颈分析

在同步时序电路中，所有触发器的传输延迟和建立时间基本相同，唯一的差异在于组合电路部分。因此，整个电路的最高工作频率取决于最大的组合电路延迟（"最大的那朵云"）。应找出整个同步时序电路中最长的组合电路路径，以其对应的工作周期作为整个电路的工作周期。

如果时序约束不满足，唯一的办法是增加组合电路的延迟（"把云彩拉大"），但这必然会降低工作频率——改善一个性能时，另一个性能会牺牲。

## 流水线

流水线（Pipeline）是触发器在数字电路中的一类典型应用，在当前的CPU设计中广泛使用（如Intel处理器宣传的"几级流水线工艺"）。

### 流水线的思想来源：洗衣房类比

以美国大学宿舍洗衣房为例：洗衣机洗一锅30分钟，干衣机烘干60分钟。洗一次完整的衣服需要90分钟。

- **串行方式（类比组合电路）**：洗完一锅后，放入干衣机，等干衣机完成后再洗下一锅。每锅衣服需要90分钟，每90分钟出一锅干净衣服。
- **流水线方式**：洗完一锅后放入干衣机，洗衣机空出来后立即洗下一锅，不用等干衣机完成。一旦稳定后，每60分钟出一锅干净衣服，但第一锅衣服从进来到出去需要120分钟。

### 延迟与吞吐率

流水线引入了两个关键概念：

- **延迟（Latency）**：单个任务从进入系统到离开系统所需的总时间。
- **吞吐率（Throughput）**：系统在单位时间内能处理的任务数量。

| 方式 | 延迟（每锅） | 吞吐率 |
|------|-------------|--------|
| 串行（Harvard方式） | 90分钟 | 90分钟/锅 |
| 流水线（MIT方式） | 120分钟 | 60分钟/锅 |

流水线以增加单任务的延迟为代价，换取了更高的吞吐率。

### 组合电路的流水线

在数字电路中，组合电路的计算过程是串行的——前面的模块算完后后面的模块才开始算，但前面的模块实际上已经空闲，却无法接收新数据。

> [!example] 例：三级组合电路的流水线改造
> 一个三级组合电路，各模块延迟分别为 $t_F = 5\text{ns}$、$t_G = 10\text{ns}$、$t_H = 30\text{ns}$，总延迟为 $45\text{ns}$。
>
> 若无流水线，每 $45\text{ns}$ 才能输入一个新数据，所有模块只在部分时间有效工作，其余时间在等待。
>
> **解：** 若加入两级流水线，在 $F$ 的输出端和 $G$ 的输出端分别插入触发器存储中间结果，各触发器使用同一时钟。改造后的流水线周期由最慢的一级决定，即 $\max(5, 10, 30) = 30\text{ns}$，再加上触发器的建立时间。吞吐率从每 $45\text{ns}$ 一次提升为每 $30\text{ns}$ 一次，但单个数据的延迟变为 $30 \times 3 = 90\text{ns}$（含三级流水线）。

### 流水线设计规则

将任意组合电路改造为流水线时需遵循以下规则：

> [!important] 流水线设计要点
> 1. K级流水线意味着从输入到输出的每一条路径上都恰好经过K个触发器，必须保持一致。
> 2. 触发器应从输出端开始逐级加入，不要从输入端加入。
> 3. 所有触发器共用同一时钟。
> 4. 时钟周期应大于最长的组合逻辑延迟加上触发器的建立时间。

### 错误示例

将流水线触发器放在输入端，或者各级之间触发器数量不一致，都属于错误的流水线设计，无法改善电路性能。

### 图形化流水线设计方法

设计流水线时可使用图形方法：

1. 将组合电路展开为图形，在上下两侧各标记起点和终点。
2. 第一级流水线必须加在输出端。
3. 找出延迟最大的路径（瓶颈），优先拆分它。
4. 后续流水线级应使各级延迟尽可能均衡。
5. 比最大延迟小的路径不必再拆分，因为整体工作频率由最长的路径决定。
6. 延迟（Latency）= 级数 $\times$ 最长级延迟。

> [!example] 例：图形化流水线设计
> 一个组合电路中存在一条 $8\text{ns}$ 的路径，其余路径分别为 $3\text{ns}$ 和 $4\text{ns}$。
>
> **解：** 优先将 $8\text{ns}$ 的路径单独作为一级，其余路径与它搭配以均衡各级延迟。由于 $3 + 4 = 7 < 8$，因此即使将 $3\text{ns}$ 和 $4\text{ns}$ 的路径拆分，也不会改善整体工作频率（仍受 $8\text{ns}$ 限制）。最终工作周期为 $8\text{ns}$ 加上触发器建立时间。

### 突破瓶颈：硬件并行

当吞吐率受限于最慢一级时，可以像洗衣房增加设备一样，复制瓶颈部分的硬件电路使其并行工作。例如，将一个 $8\text{ns}$ 的模块复制一份，两个模块交替接收数据，配合数据选择与切换电路，可将等效延迟降低到 $4\text{ns}$，从而使工作频率提高一倍。

## 本讲小结

| 知识点 | 要点 |
|--------|------|
| 保持时间约束 | $t_{CQ} + t_{CQ} > t_H$ |
| 最小工作周期 | $T_{CLK(min)} = t_{PD(max)} + t_{CQ} + t_{SU}$ |
| 最高工作频率 | $f_{max} = 1 / T_{CLK(min)}$ |
| 瓶颈来源 | 最长的组合电路路径 |
| 流水线目的 | 提高吞吐率（以增加延迟为代价） |
| 流水线规则 | K级流水线每路径K个触发器，从输出端加，时钟共用 |
| 时钟周期设置 | 大于最长组合延迟 + 触发器建立时间 |
| 进一步提速 | 复制瓶颈硬件，并行处理 |

### 核心公式/结论

- 保持时间约束：$t_{CQ} + t_{CQ} > t_H$
- 最小工作周期：$T_{CLK(min)} = t_{PD(max)} + t_{CQ} + t_{SU}$
- K级流水线的延迟 = 级数 $\times$ 最长级延迟
- K级流水线的吞吐率 = 最长级延迟的倒数
