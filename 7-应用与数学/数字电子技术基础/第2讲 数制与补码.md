
# 数制与补码

> [!abstract] 本讲定位
> 建立编码的基本概念和等长编码公式。掌握常用数制及其转换。重点理解原码的缺陷、补码的编码原理与运算方法。了解 BCD 码。

## 编码与等长编码

编码是对信息进行描述和表示的过程。核心原则是**唯一性**：不同编码必须对应不同事物，相重则无法区分。

若有 $n$ 种可能结果，编码位数 $m$ 需满足 $2^{m-1} < n \le 2^m$，即 $m = \lceil \log_2 n \rceil$。例如一枚骰子有六种结果，需三位二进制；两枚骰子 36 种结果，需六位。十进制数一位共 10 种状态，需四位二进制，这就是 BCD 码的基本思想。

## 数制

数字电路中常用二进制、八进制、十进制、十六进制。对于任意 $N$ 进制，数码取值范围为 $0 \sim (N-1)$，逢 $N$ 进一。数制并不固定，只要有需要就可以设计任意进制。

任意进制转十进制，按权值展开求和。二进制与八进制互转时每三位一组，与十六进制互转时每四位一组。

> [!note] 小数点处理
> 将非十进制小数转换为十进制时，将小数点后每一位按负幂次权值相加即可，无需纠结小数点在原进制下的含义。

## 原码与补码

### 原码的问题

二进制中无法直接写 "+" "-"，必须用一位二进制区分正负：0 正 1 负，其余位表示数值大小。这就是原码。

以四位原码为例：$+5$ 为 $0\,101$，$-5$ 为 $1\,101$。按理说 $+5 + (-5) = 0$，但实际计算 $0101 + 1101 = 10010 \neq 0$。同样 $+4 + (-4)$ 也不会归零，$+6 + (-6)$ 又会得到另一个"零"。

问题的根源：符号位属于码制，表示"正"或"负"这个事物；数值位属于数制，表示大小。将码制和数值混合编码后再按数值运算规则处理，必然出错。

此外，原码还存在**正零** $0\,000$ 和**负零** $1\,000$ 并存的编码浪费。同一个零占了两组编码。

> [!warning] 原码的缺陷
> 1. 绝对值相等的正负数相加不能归零
> 2. 正零和负零并存，浪费编码
> 3. 根本原因：符号位是码制、数值位是数制，混合编码无法正确参与数值运算

### 补码的编码原理

补码正是为了解决原码的问题。核心思想：**最高位赋予负的权值**，其余位均为正权值。这样符号位本身就是数值的一部分，整个编码可以按纯数值方式参与运算。

以四位补码为例，权值分布为 $-8,\;4,\;2,\;1$。取值范围 $-8 \sim +7$，共 16 个数，与四位无符号数个数相同，区别在于用了一半编码表示负数。正数最大值 $+7$ 与负数绝对值最大值 $8$ 不对称，原因是零占了一组编码。

> [!important] 补码的核心
> 一串二进制数如果是补码，最高位带有负权值。读出十进制值时直接按权相加即可：$1101_{\text{补}} = -8 + 4 + 0 + 1 = -3$。

### 十进制转补码

**正数**：补码与原码相同。最高位必为 0。

**负数**：先写出绝对值的原码，然后**每位取反，末位加一**。

> [!example] -5 的五位补码
> 求十进制数 $-5$ 的五位二进制补码。
>
> **解：**
> 法一（权值法）：五位补码最高位权值为 $-16$。$-16 + 11 = -5$，偏移量为 $11$，其二进制为 $01011$。将最高位置 1 以激活负权值，得 $11011$。
>
> 法二（取反加一法）：$+5$ 的原码为 $00101$，取反得 $11010$，加一得 $11011$。
>
> 两种方法结果一致。

> [!tip] "加一" 加在哪
> 取反后的"加一"是加在二进制数的**最低有效位**。含小数时加在最末位，不是加在数值上的一。

### 补码的位扩展

正数前面补 0，负数前面补 1。负数补 1 的原因：扩展后新增的 1 的权值叠加抵消后，仍等于原来最高位的负权值，数值保持不变。

### 补码加法运算

补码最大的优势：将加减统一为加法。减一个数等于加它的补码。

> [!example] 六位补码计算 13+10 和 13-10
> 已知十进制数 $13$ 和 $10$，用六位二进制补码分别计算 $13+10$ 和 $13-10$。
>
> **解：** 首先确定位数。六位补码范围 $-32 \sim +31$，运算结果最大 $23$ 在此范围内。
>
> $13$ 的补码：$001101$
> $10$ 的补码：$001010$
> $-10$ 的补码：取反 $110101$，加一得 $110110$
>
> $13 + 10 = 001101 + 001010 = 010111 = +23$
>
> $13 - 10 = 001101 + 110110 = 1\,000011$，最高位进位舍去，得 $000011 = +3$。

> [!danger] 位数不足导致溢出
> 若用五位补码，其范围仅 $-16 \sim +15$，$13+10=23$ 超出范围，结果会显示为负数。必须根据运算结果的最大可能值选择足够位数。

### 原码与补码对照

| 十进制 | 原码 | 补码 |
|--------|------|------|
| +7 | 0111 | 0111 |
| +5 | 0101 | 0101 |
| +1 | 0001 | 0001 |
| 0 | 0000 / 1000 | 0000 |
| -1 | 1001 | 1111 |
| -5 | 1101 | 1011 |
| -8 | — | 1000 |

> [!warning] 补码易错点
> 1. 取值范围不对称：$n$ 位补码范围 $-2^{n-1} \sim +(2^{n-1}-1)$，正数最大值比负数绝对值最大值小 1
> 2. 补码直接看出大小不直观，需按权值计算
> 3. 运算前必须确认位数足够覆盖所有可能结果

## 码制

### 数制与码制

|      | 数制         | 码制      |
| ---- | ---------- | ------- |
| 表达对象 | 数量大小       | 事物      |
| 参与运算 | 数值运算       | 逻辑运算    |
| 例子   | $0101 = 5$ | 学号、身份证号 |
|      |            |         |
|      |            |         |

这一区分并不绝对，但有助于理解编码的两种用途。

### BCD 码

BCD 码用二进制编码表示十进制数。四位二进制可表示 16 种状态，十进制只需 10 种，因此编码方案不唯一。

**8421 码**按二进制自然权值编码，$0 \sim 9$ 对应 $0000 \sim 1001$。但 8421 码存在进位缺陷：$9+2$ 时 $1001+0010=1011$，$1011$ 不在有效编码范围内，无法自动产生正确的 BCD 进位。正确的 BCD 结果应为 $0001\;0001$，即高位进位 1、低位本位 1。

**余三码**正是为了解决 8421 码的进位问题而提出。它在 8421 码基础上加 3，使两个余三码相加时能自动产生进位，再经修正得到正确结果。当然，这一改进也会带来其他代价。工程设计中，达成一项性能往往需要牺牲另一项性能。

> [!important] 编码不唯一
> 四位二进制有 16 种状态，只需选 10 种表示十进制数，只要不重码即可。不同应用场景催生不同的编码方案。

## 本讲小结

### 原码与补码

| | 原码 | 补码 |
|------|------|------|
| 最高位 | 符号位，不参与数值 | 负权值，参与数值运算 |
| 零的表示 | 正零和负零两组编码 | 只有一组编码 |
| 加法 | 正负数相加不能归零 | 正负数相加正确归零 |
| 根本区别 | 码制与数制混合编码 | 纯数值编码 |

补码计算：正数同原码，负数取反加一。$n$ 位补码范围 $-2^{n-1} \sim +(2^{n-1}-1)$。
