# 信息与编码 第二讲

> [!abstract] 本讲定位
> 承接第一讲信息度量的概念，深入讲解编码的基本原理、数制转换、二进制补码的编码规则与应用，以及常见的码制（BCD码、ASCII码等）。

## 编码的基本概念

编码是对信息进行描述和表示的过程，同时也是对信息的一种度量。

### 编码的唯一性

编码的关键原则是**唯一性**——不同的编码必须对应不同的事物。如果编码相重，在处理过程中将无法区分。这就像人的名字不能重复一样，当出现重名时，需要借助其他信息（如时间轴、上下文）来辅助区分。

### 编码的多样性

同一事物在不同情境下可以有不同编码。以一名同学为例：他有自己的名字、学号、室友间的昵称，每个都是不同的编码方式，但都指向同一个人。编码方式取决于应用背景和环境。

### 编码的要素

编码会对整个系统的设计产生多方面的影响，涉及以下要素：

- **编码机制**：什么样的环境和使用条件
- **编码有效位**：编码的效率
- **编码的可靠性**
- **编码的安全性**

### 等长编码

等长编码是指每个事物分配到的码的长度一致，如学号、车牌号都是等长编码。

一般地，若有 $n$ 种可能结果，编码位数 $m$ 需满足 $2^{m-1} < n \le 2^m$，即 $m = \lceil \log_2 n \rceil$。例如，扔硬币有正反两种结果，用一位二进制即可表示；一枚骰子有六种结果，则需要三位二进制编码；两枚骰子有 36 种结果，需要六位二进制编码。

十进制数一位（0~9）共 10 种状态，需要四位二进制编码，这就是 BCD 码（Binary-Coded Decimal）的基本思想——每个十进制位用四位二进制表示。

## 数制

### 常用进制

日常生活中最常用的是十进制，但数制并不唯一。数字电路中常用的进制有：

| 进制 | 基数 | 数码范围 | 进位规则 |
|------|------|----------|----------|
| 二进制 | 2 | 0~1 | 逢二进一 |
| 八进制 | 8 | 0~7 | 逢八进一 |
| 十进制 | 10 | 0~9 | 逢十进一 |
| 十六进制 | 16 | 0~9, A~F | 逢十六进一 |

### 进制间的转换

**任意进制转十进制**：按权值展开求和。

二进制数每一位的权是以 2 为底的幂，与十进制规则完全一致。例如：

$$(1011.101)_2 = 1 \times 2^3 + 0 \times 2^2 + 1 \times 2^1 + 1 \times 2^0 + 1 \times 2^{-1} + 0 \times 2^{-2} + 1 \times 2^{-3}$$

**二进制与八进制/十六进制的转换**：

- 二进制转八进制：每三位一组对应一位八进制数
- 二进制转十六进制：每四位一组对应一位十六进制数

### 任意进制

数制并不固定，只要有需要就可以设计任意进制：

- **十二进制**：时间（小时、月份）
- **六进制**：时间（分钟、秒）
- **三进制**：某些场景下也可使用

对于任意 $N$ 进制，数码 $k$ 的取值范围是 $0 \sim (N-1)$，进位规则为逢 $N$ 进一。

> [!note] 小数点处理
> 将非十进制小数转换为十进制时，只需将小数点后的每一位按其权值（负幂次）相加即可，无需纠结小数点在原进制下的含义。

## 二进制数的正负表示

### 原码表示法及其问题

在二进制世界中，正负号无法像十进制那样直接加"+"或"-"，必须用一位二进制数来区分。通常用 0 表示正，1 表示负。

> [!example] 例：验证原码表示法的缺陷
> 用四位原码（最高位为符号位，0 正 1 负，其余三位为数值位）表示 $+5$ 和 $-5$，验证二者相加能否归零。若不能，分析原因。
>
> $+5$ 的原码为 $0\,101$，$-5$ 的原码为 $1\,101$。二者相加：$0101 + 1101 = 10010 \neq 0$，不能归零。
>
> **解：** 符号位表示正/负（属于码制），数值位表示大小（属于数制）。将码制和数值混合编码后按数值运算规则处理，必然出错。同样，$+4$ 加 $-4$ 也会得到另一个非零值。此外，原码还存在正零（$0\,000$）和负零（$1\,000$）并存的编码浪费。

> [!warning] 原码的缺陷
> 1. 绝对值相等的正负数相加不能归零
> 2. 出现正零和负零，浪费一组编码
> 3. 根本原因：符号位（码制）和数值位（数制）混合编码后参与数值运算

### 二进制补码

二进制补码是为了解决原码的问题而提出的编码方式，它将正负数完全用数值方式表达，使正负数加法运算能正确归零。

#### 编码原则

补码的最高位不仅表示符号，还带有**负的权值**，其余位均为正权值。

以四位二进制补码为例：

$-2^3 \quad 2^2 \quad 2^1 \quad 2^0$
$-8 \quad 4 \quad 2 \quad 1$

由此可得，四位二进制补码的取值范围为 $-8 \sim +7$，共 16 个数，与四位无符号数的个数相同，区别在于用了一半编码表示负数。正数最大值（7）与负数绝对值最大值（8）不对称，原因是"零"（0000）占用了一组编码。

> [!example] 例：负一在四位补码中的表示
> 已知四位补码中 $1000$ 表示 $-8$。问：$-1$ 应如何用四位补码表示？验证你的答案。
>
> **解：** 要表示 $-1$，需借助最高位的负权值：$-8 + 7 = -1$，因此 $-1 = 1000 + 0111 = 1111$。
>
> 验证：$1111$ 作为补码，按权值计算：$-8 + 4 + 2 + 1 = -1$。将 $1111$（-1）与 $0001$（+1）相加得 $10000$，进位溢出后余 $0000 = 0$，正负数相加成功归零。

#### 补码的计算方法

**补码转十进制**：按权值相加即可。

$$1101_{\text{补}} = -8 + 4 + 0 + 1 = -3$$

**十进制转补码**：

- **正数**：补码与原码相同
- **负数**：先写出绝对值的原码，然后**每位取反，末位加一**

> [!example] 例：负五的五位二进制补码
> 试用两种方法求 $-5$ 的五位二进制补码。
>
> **解：** 五位二进制补码最高位权值为 $-16$。
>
> 法一（权值法）：$-16 + 11 = -5$，$11$ 的二进制为 $01011$，故负五的补码为 $11011$。
>
> 法二（取反加一法）：正五的原码为 $00101$，取反得 $11010$，加一得 $11011$。两种方法结果一致。

> [!tip] 取反加一"加一"的位置
> 当被转换的数含小数时，"加一"是加在二进制数的最末位（最低有效位），即加在二进制数最后的那个一上。

#### 补码的位扩展

符号位扩展原则——正数前面补 0，负数前面补 1。例如，正五从五位 $00101$ 扩展到八位为 $00000101$；负五从五位 $11011$ 扩展到八位为 $11111011$。负数补 1 的原因是：扩展后所有新增的"1"的权值叠加抵消后，仍等于原来最高位的负权值，数值保持不变。

#### 补码加法运算

补码的最大优势在于将加减运算统一为加法运算。减法时，只需将减数取负（即用其补码表示），然后相加即可。

> [!example] 例：补码加法运算——13+10 与 13-10
> 用六位二进制补码计算 $13+10$ 和 $13-10$ 的结果。
>
> **解：**
>
> 首先确定位数。六位补码的取值范围为 $-32 \sim +31$，13 和 10 的运算结果（最大 23）在此范围内。
>
> $13$ 的补码：$001101$
>
> $10$ 的补码：$001010$
>
> $-10$ 的补码：先取反得 $110101$，加一得 $110110$
>
> $13 + 10 = 001101 + 001010 = 010111 = +23$
>
> $13 - 10 = 001101 + 110110 = 1000011$ → 最高位进位舍去，得 $000011 = +3$
>
> 运算结果正确。当位数选择合理、取值范围足够时，进位不影响结果，可直接忽略。

> [!danger] 位数不足会导致溢出
> 如果按同学最初提议的用五位二进制补码（范围 $-16 \sim +15$），$13+10=23$ 已超出正数最大值 15，结果会显示为负数，造成严重错误。
>
> 因此，位数选择必须留够余量，确保编码范围覆盖所有可能的运算结果。

### 补码与原码的对照

| 十进制 | 四位原码 | 四位补码 |
|--------|----------|----------|
| +7 | 0111 | 0111 |
| +6 | 0110 | 0110 |
| +5 | 0101 | 0101 |
| +4 | 0100 | 0100 |
| +3 | 0011 | 0011 |
| +2 | 0010 | 0010 |
| +1 | 0001 | 0001 |
| 0 | 0000 / 1000 | 0000 |
| -1 | 1001 | 1111 |
| -2 | 1010 | 1110 |
| -3 | 1011 | 1101 |
| -4 | 1100 | 1100 |
| -5 | 1101 | 1011 |
| -6 | 1110 | 1010 |
| -7 | 1111 | 1001 |
| -8 | — | 1000 |

> [!warning] 补码的易错点
> 1. 取值范围的不对称性：正数最大值比负数绝对值最大值小 1（零占了一位）
> 2. 补码直接看出大小不直观，需按权值计算
> 3. 补码运算时必须保证位数足够，否则溢出导致符号翻转

## 码制

### 数制与码制的区别

| 类型 | 表达对象 | 参与运算 | 例子 |
|------|----------|----------|------|
| 二进制数（数制） | 数量大小 | 数值运算 | $0101 = 5$ |
| 二值逻辑（码制） | 事物 | 逻辑运算 | 学号、身份证号 |

二进制数表达大小时参与的是数值运算；表达事物时参与的是逻辑运算。但这一区分并不绝对。

### 常见码制

#### BCD 码（Binary-Coded Decimal）

BCD 码是用二进制编码表示十进制数。四位二进制可表示 16 种不同状态，而十进制只需要 10 种，因此同一编码方案并非唯一——只要不重码即可，不同应用背景催生出不同的 BCD 编码方式。

##### 8421 码（自然权值码）

最直接的 BCD 码，按二进制自然权值编码：

| 十进制 | 8421 码 |
|--------|---------|
| 0 | 0000 |
| 1 | 0001 |
| 2 | 0010 |
| 3 | 0011 |
| 4 | 0100 |
| 5 | 0101 |
| 6 | 0110 |
| 7 | 0111 |
| 8 | 1000 |
| 9 | 1001 |

> [!example] 例：8421 码的进位缺陷
> 用 8421 码计算 $9 + 2$，观察结果是否有效，并分析原因。
>
> $9 = 1001$，$2 = 0010$
>
> $1001 + 0010 = 1011$
>
> **解：** $1011$ 对应十进制 11，但在 8421 码中 $1011$ 并不是有效编码（有效范围仅为 $0000 \sim 1001$）。正确的 BCD 结果应是 $0001\,0001$（进位 1，本位 1），但 8421 码无法自动产生正确的进位。这就是 8421 码在加法运算中的缺陷。

##### 余三码（Excess-3 Code）

余三码是在 8421 码基础上加 3 得到：

| 十进制 | 余三码 |
|--------|--------|
| 0 | 0011 |
| 1 | 0100 |
| 2 | 0101 |
| 3 | 0110 |
| 4 | 0111 |
| 5 | 1000 |
| 6 | 1001 |
| 7 | 1010 |
| 8 | 1011 |
| 9 | 1100 |

余三码的提出正是为了解决 8421 码的进位问题。当两个余三码相加时，能自动产生进位，再通过修正得到正确结果。当然，这一改进也会带来其他方面的代价——在工程设计中，达成一项性能往往需要牺牲另一项性能。

#### ASCII 码

ASCII 码是最常见的字符编码，采用**七位**等长编码，共编码 86 个字符（包括大写字母、小写字母、数字、标点符号和控制字符）。每个字符都用一串七位二进制 01 串唯一表示。

> [!important] 等长编码的原则
> 等长编码遵循的最根本原则是：所选择的码长足以区分不同的事物即可。即在满足区分度的前提下，追求最短编码长度。

## 本讲小结

| 知识点 | 要点 |
|--------|------|
| 编码基本原则 | 唯一性（不重码），同一事物在不同场景可有不同编码 |
| 等长编码 | $n$ 种事物需 $m = \lceil \log_2 n \rceil$ 位编码 |
| 数制 | 二进制、八进制、十进制、十六进制，以及任意进制 |
| 进制转换 | 按权值展开求和；二←→八（三位一组）；二←→十六（四位一组） |
| 补码 | 最高位为负权值，解决正负数加法归零问题 |
| 补码计算 | 正数同原码；负数取反加一 |
| 位扩展 | 正数前补 0，负数前补 1 |
| BCD 码 | 8421 码（自然权值）、余三码（解决进位问题） |
| 码制与数制 | 数制表达数量（数值运算），码制表达事物（逻辑运算） |

### 核心公式/结论

- 补码加法：选择合适的编码位数，确保取值范围覆盖运算结果，进位可忽略
- 补码转换：正数补码同原码；负数补码 $=$ 原码取反 $+1$（加在最低位）
- 取值范围：$n$ 位补码范围 $-2^{n-1} \sim +(2^{n-1} - 1)$
