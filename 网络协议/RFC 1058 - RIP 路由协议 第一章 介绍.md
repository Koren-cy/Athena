# RFC 1058 — RIP 路由信息协议

## 概述

RFC 1058 定义了一个基于 **Bellman-Ford（距离向量）算法** 的路由协议。该协议在 ARPANET 早期就已开始使用。其数据包格式和协议源自 Berkeley Unix 中的 **routed** 程序，该程序已成为网关和主机之间交换路由信息的**事实标准**。大多数商用 IP 网关厂商都实现了该协议，同时许多厂商也保留了内部使用的专有协议。该协议最适用作 **内部网关协议（Interior Gateway Protocol, IGP）**。

## 工作原理简述

RIP 运行于基于 IP 的互联网：

- 互联网由**网络**组成，通过**网关**连接。
- 网络可以是：
  - **点对点链路**（PPP、专线等）
  - **复杂网络**（Ethernet、ARPANET 等）
- **路由**的任务：决定主机或网关将 IP 数据报发往何处。
  - 如果目的地在**直连网络**上 → 直接发送。
  - 否则 → 发送给更靠近目的地的**下一跳网关**。
- 路由协议的职责很简单：**提供路由所需的信息**。

## §1.1 协议的局限性

### 限制一：最大 15 跳

> 协议只能处理最长路径为 **15 跳** 的网络。

- 设计者认为该协议的基本设计**不适合更大规模的网络**。
- 前提假设：每跳开销 = 1（RIP 的默认配置）。
- 如果管理员使用更大的开销值，15 的上限会**更快被消耗殆尽**。

### 限制二：「计数到无穷大」问题

> 协议依赖「计数到无穷大」来解决某些异常情况。

- 如果系统包含数百个网络，且一个路由回环涉及所有网络 → 解决该回环需要**大量时间或带宽**。
- 回环在被纠正前会**消耗大量网络带宽**。
- 在实际案例中，这通常不是问题（除了慢速线路），即便如此，也有各种预防措施可以避免。

> ⚠️ **「计数到无穷大」**是距离向量协议的经典问题：当路由失效时，路由器之间的更新循环使跳数不断递增，直到达到 infinity（在 RIP 中 = 16）。

### 限制三：固定度量

> 协议使用**固定度量（metrics）**来比较路由。

- **不适用**的场景：需要基于实时参数选择路由：
  - 测量到的延迟（delay）
  - 可靠性（reliability）
  - 负载（load）
- 若扩展以支持这些指标，**很可能引入协议设计无法处理的某种不稳定性**。

## §1.2 文档结构

RFC 1058 的主体由两部分组成：

| 章节 | 内容 | 特点 |
|------|------|------|
| **§2** | 距离向量算法的概念发展及合理性证明 | - 采用「螺旋法」的非正式呈现<br>- 从简单算法开始，逐步添加改进<br>- 可独立阅读 |
| **§3** | 正式协议规范 | - 可直接用于实现 RIP<br>- 除明确引用 §2 处之外，阅读 §3 即可完整实现<br>- 可独立阅读 |

## 关键术语速查

| 术语           | 英文                              | 含义                              |
| ------------ | ------------------------------- | ------------------------------- |
| 距离向量         | Distance Vector                 | 基于到目标网络的距离（跳数）来选择路由的算法          |
| Bellman-Ford | Bellman-Ford                    | 距离向量算法的数学基础，源于动态规划中的 Bellman 方程 |
| 自治系统         | Autonomous System (AS)          | 由单一实体管理的网络集合                    |
| 内部网关协议       | Interior Gateway Protocol (IGP) | AS 内部的路由协议                      |
| 外部网关协议       | Exterior Gateway Protocol (EGP) | AS 之间的路由协议                      |
| 路由回环         | Routing Loop                    | 数据包在多个路由器间无限循环转发的异常状态           |
| 计数到无穷大       | Counting to Infinity            | 距离向量协议中解决路由回环的机制：跳数持续递增直到达到上限   |
| 度量           | Metric                          | 用于比较路由优劣的数值（RIP 中 = 跳数）         |
