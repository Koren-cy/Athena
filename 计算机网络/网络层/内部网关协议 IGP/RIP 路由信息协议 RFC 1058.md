# RIP 路由信息协议（RFC 1058）

## 一、协议定位：RIP 在网络世界的角色

### 1.1 问题背景

互联网由成千上万个自治系统（Autonomous System, AS）组成。在一个 AS **内部**，路由器需要一种机制来彼此告知：「我能到达哪些网络，距离是多少」。这就是**内部网关协议（Interior Gateway Protocol, IGP）** 的职责。

RIP（Routing Information Protocol）是最早被广泛使用的 IGP 之一。它源自 BSD Unix 系统的 `routed` 程序，于 1988 年 6 月由 RFC 1058 正式标准化。

### 1.2 一句话概括

> RIP 是一个基于 **距离向量（Distance Vector）** 算法的路由协议。每台路由器周期性地向邻居广播自己的整张路由表，邻居据此更新自己的路由表，最终全网所有路由器对「到达每个目的地的最佳下一跳」达成一致。

### 1.3 适用的网络规模

RIP 被设计用于 **中等规模、技术同构** 的网络。其核心约束是：**网络直径不超过 15 跳**。超过这个规模，RIP 不适合，需要使用 OSPF 等链路状态协议。

## 二、核心算法：Bellman-Ford 距离向量

### 2.1 数学模型

RIP 的数学基础是 Bellman 方程。对于网络中的任意两个实体 $i$ 和 $j$：

- $d(i, j)$：$i$ 和 $j$ 之间的**直接代价**（若不相邻则为无穷大）
- $D(i, j)$：从 $i$ 到 $j$ 的**最佳路由的度量值**

Bellman 方程：

$$D(i, j) = \min_{k \in \text{neighbors}(i)} [d(i, k) + D(k, j)]$$

这个方程的直觉含义是：

> 从 $i$ 到 $j$ 的最短距离 = 从 $i$ 的所有邻居中选择一条路径：先到邻居 $k$，再从 $k$ 到目的地 $j$，取总代价最小的那条。$D(i, i) = 0$。

### 2.2 路由表结构

每台运行 RIP 的路由器维护一张**路由表**，每条表项包含：

| 字段 | 含义 |
|-------|------|
| **目的地址** | 目标主机或网络的 IP 地址 |
| **下一跳（Gateway）** | 通往该目的的下一跳路由器地址 |
| **接口（Interface）** | 从哪个物理网络接口出去 |
| **度量值（Metric）** | 到达该目的地的距离（1~15，16 = 无穷大/不可达） |
| **定时器（Timer）** | 自上次更新以来经过的时间 |

### 2.3 增量更新 vs 全量计算

RIP 不每次重新计算全局最小值，而是采用**增量更新**策略：

> **规则 1（更好的路由）**：收到邻居 $G'$ 发来的更新，对其中每条路由，加上本地网络代价得到 $D'$。若 $D' < 当前度量值$，则采用这条新路由（下一跳设为 $G'$）。

> **规则 2（来自当前下一跳的更新，必须接受）**：若发送更新的 $G'$ 恰好是某个目的地的**当前下一跳**，则**无条件接受**新的度量值——即使它变大了。

为什么规则 2 至关重要？

假设路由器 A 通过路由器 B 到达网络 N，度量值为 3。某天 B 到 N 的路径变差，度量值变成 10。B 告诉 A：「到 N 现在要 10 跳了。」如果 A 拒绝接受（因为 10 > 3），A 的路由表会永远停留在过时的 3，形成**黑洞**。规则 2 保证了坏消息能够传播。

### 2.4 "通告的是我已有的，而不是我重新计算的"

每个路由器发送的是**自己的路由表**，而不是帮邻居重新计算。邻居收到后，加上双方共享网络的代价，再决定是否更新自己的路由表。这种「各管各的」分布式计算方式，是距离向量协议的本质特征。

## 三、消息格式与传输

### 3.1 传输层

RIP 运行在 **UDP 端口 520** 上：

- 主动发送的更新：源端口和目的端口都是 520
- 响应请求：发送到请求方的源端口
- 静默 RIP 进程：只监听，不主动发送

### 3.2 数据报结构

每个 RIP 数据报最大 **512 字节**（不含 IP/UDP 头），最多携带 **25 条路由条目**。

```
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|  command (1)  |  version (1)  |       must be zero (2)        |
+---------------+---------------+-------------------------------+
| address family identifier (2) |       must be zero (2)        |
+-------------------------------+-------------------------------+
|                        IP address (4)                         |
+---------------------------------------------------------------+
|                        must be zero (4)                       |
+---------------------------------------------------------------+
|                        must be zero (4)                       |
+---------------------------------------------------------------+
|                         metric (4)                            |
+---------------------------------------------------------------+
```

- 所有整数采用**网络字节序（大端序）**
- 命令字段：1 = 请求（Request），2 = 响应（Response）
- 地址族标识符：IP = 2
- 度量值字段占 4 字节，有效值 1~15，16 = 无穷大（不可达）

### 3.3 RIP 的五种命令

| 值 | 命令 | 说明 |
|----|------|------|
| 1 | Request | 请求对方发送路由表（全部或部分） |
| 2 | Response | 包含路由表数据的更新或回复 |
| 3 | Traceon | 已废弃，应忽略 |
| 4 | Traceoff | 已废弃，应忽略 |
| 5 | Reserved | Sun Microsystems 保留使用 |

### 3.4 请求-响应机制

**全表请求**：发送一条 AFI = 0、Metric = 16 的条目 → 对方回复整张路由表（应用水平分割和子网过滤）。

**特定条目请求**：逐条指定目的地址 → 对方逐个查找，找到则返回实际度量值，找不到返回 16。**不应用水平分割。**

## 四、定时器机制：协议的时间骨架

RIP 的运作由三种定时器驱动：

| 定时器 | 时长 | 作用 |
|--------|------|------|
| **定期更新计时器** | 30 秒 | 每隔 30 秒向所有邻居广播整张路由表 |
| **路由超时计时器** | 180 秒 | 若 180 秒内未收到某条路由的更新，标记为失效 |
| **垃圾回收计时器** | 120 秒 | 路由被标记为不可达（metric = 16）后，再保留 120 秒然后彻底删除 |

### 4.1 为什么要加随机抖动？

RFC 1058 明确规定：30 秒定时器**不能精确地**每隔 30 秒触发，必须添加一个**小的随机偏移**。

**原因**：在广播网络上，如果多台路由器恰好同步会在同一瞬间广播更新，会导致：
- 所有路由器同时发送 → 网络瞬间拥堵
- 所有路由器同时接收 → CPU 瞬间过载
- 碰撞 → 某些更新丢失 → 路由不稳定

通过添加随机抖动（几十到几百毫秒），让路由器彼此错开发送时间。

### 4.2 路由删除的四步过程

```
正常路由（metric = N）
    │
    ├─ 180 秒无更新（或收到 metric = 16）
    │
    ▼
标记为不可达（metric = 16），启动垃圾回收计时器（120 秒）
    │
    │  在此期间：
    │  - 路由不参与数据转发
    │  - 更新中携带 metric = 16 通知邻居
    │
    ▼
垃圾回收计时器到期 → 彻底删除路由
```

如果在垃圾回收期间出现了到同一目的地的**新有效路由**，新路由直接替换旧条目，垃圾回收计时器取消。

## 五、输入处理：收到更新后做什么

### 5.1 验证检查

收到一个 Response 前，必须通过以下验证：

1. **源端口必须是 520**（来自非 520 端口的响应被丢弃）
2. **源地址必须在直连网络上**（不信任来自非邻居的更新）
3. **不能来自自身地址**（防止处理自己的广播）
4. 逐条检查：metric > 16 → 忽略；不支持的 AFI → 忽略；非法地址类别 → 忽略

### 5.2 度量值计算

收到的每条路由的度量值加上**到达网络的开销**（默认加 1），再与 16 取最小值：

```
新度量值 = MIN(收到的度量值 + 到达网络开销, 16)
```

### 5.3 路由更新决策表

| 场景 | 动作 |
|------|------|
| **新路由**（目的地在表中不存在）且 metric < 16 | 添加，设置下一跳为发送者 |
| **同一下一跳，不同度量值** | **无条件接受新度量值**（规则 2），即使变大了 |
| **同一下一跳，metric = 16** | 启动删除流程（标记不可达，开始垃圾回收） |
| **不同下一跳，更小度量值** | 切换到新下一跳（更好的路由） |
| **不同下一跳，相同度量值** | 可选：若现有路由已过半衰期，切换到新网关；否则忽略 |
| **相同度量值，相同下一跳** | 仅重置超时计时器 |

## 六、输出处理：什么时候发送更新

### 6.1 三种触发场景

| 触发条件 | 发送对象 |
|----------|----------|
| **定期更新**（每 30 秒） | 所有邻居 |
| **触发更新**（路由度量值发生变化时） | 所有邻居 |
| **响应请求** | 仅发送给请求方 |

### 6.2 触发更新的速率限制

触发更新不是每次路由变化都立即发送。RFC 1058 规定：

> 发送触发更新后，启动一个 **1~5 秒的随机定时器**。在此期间若发生新的变化，等定时器触发时一次性发送合并后的更新。

这防止了路由抖动时产生更新风暴。

### 6.3 触发更新能消除计数到无穷吗？

**不能完全消除，但能大幅减少发生的概率。**

理想情况下，坏消息通过触发更新沿受影响路径反向级联传递，全网在几个周期内就能收敛。但现实中：
- 定期更新可能从尚未收到触发更新的路由器处传来
- 这些「过时但尚未失效」的路由可能重建已被破坏的路由残余
- 形成短暂的路由环路，发生有限次的计数

因此触发更新使计数到无穷**不太可能发生**，但**理论上仍有可能**。

## 七、水平分割与毒性反转：解决路由环路的经典方案

### 7.1 问题：为什么要限制向来源通告？

考虑这个场景：

```
A ──── B ──── C ──── 网络 N
```

B 从 C 学到到达 N 的路由。如果 B 在向 C 发送更新时，不加限制地告诉 C「我能到 N，距离 2」，那么当 C 到 N 的链路断开时：

1. C 看到 B 的通告：「到 N 距离 2」
2. C 想：「我不能直接到 N 了，但 B 说它能到，距离 2，那我通过 B 到 N 就是距离 3」
3. C 更新路由：到 N 的下一跳 = B，metric = 3
4. C 告诉 B：「到 N 距离 3」
5. B 想：「C 更新了，现在是 3，那我到 N 就是 4」
6. B → C：「到 N 距离 4」... 依此类推

**这就是计数到无穷（Counting to Infinity）**。A 和 B 互相「推卸责任」，度量值一路攀升直到 16。

### 7.2 水平分割（Split Horizon）

> **永远不要向一条路由的来源邻居通告该路由的可达性。**

两种实现方式：

- **简单水平分割**：向邻居 N 发送更新时，省略所有从 N 学到的路由
- **带毒性反转的水平分割**：向邻居 N 发送更新时，包含从 N 学到的路由，但**故意将度量值设为 16（无穷大）**

### 7.3 为什么毒性反转更优？

回到上面的例子。如果 B 使用毒性反转，在向 C 发送更新时会说「到 N 距离 16（不可达）」。当 C 到 N 的链路断开时：

1. C 看到 B 的通告：「到 N 距离 16」
2. C 知道自己也不能到 N → 立即将到 N 的路由设为 16
3. **环路立即断裂，无需等待超时**

而简单水平分割只能靠 180 秒超时来消除环路，收敛慢得多。

### 7.4 毒性反转的代价

毒性反转会增加更新消息的大小。在一个大型园区骨干网上，每台接入路由器都有一台骨干网关。骨干网关在向接入路由器发送更新时，必须列出所有从骨干网其他网关学到的路由，并将度量值设为 16——这些条目占用了更新数据报的宝贵空间却只传递「不可达」信息。

RFC 1058 允许实现者选择使用简单水平分割，或提供配置选项让网络管理员按需选择。

## 八、无穷大 = 16 的设计考量

### 8.1 为什么是 16？

这是一个精心的权衡：

> 无穷大必须**足够大**，以至于没有真实路由会达到这个值。但它**不应该比必要的更大**。

**往大里说**：无穷大越大，允许的网络直径越大。如果把无穷大设为 64，那就能支撑直径 63 跳的网络。

**往小里说**：计数到无穷时，每过一个更新周期，度量值增加 1。无穷大越小，从形成环路到路由被标记为不可达的时间越短。

**16 的选择意味着**：RIP 网络的最大直径为 15 跳。在默认每跳代价为 1 的情况下，任何需要超过 15 跳的路径都视为不可达。

### 8.2 这不只是 RIP 的限制，而是距离向量协议的内在矛盾

距离向量协议的根本问题在于：

- 要支持大网络 → 无穷大要设得大
- 无穷大设得大 → 计数到无穷的过程更长 → 坏消息传播更慢

RIP 选择站在「快速收敛」这边，以牺牲网络规模为代价。对于需要更大网络的场景，应该使用链路状态协议（如 OSPF），它们通过泛洪链路状态通告来避免计数到无穷问题。

## 九、子网与边界处理

### 9.1 最长匹配原则

RIP 路由表的查找顺序（由具体到宽泛）：

1. **主机路由**（最优先匹配）
2. **子网路由**
3. **网络路由**
4. **默认路由**（0.0.0.0）

### 9.2 边界网关的子网过滤

这是 RFC 1058 中一个容易被忽视但非常重要的规定：

> **子网路由不能发送到该子网所属网络之外。**

具体行为：
- 对于处在同一个子网化网络**内部**的邻居 → 发送子网条目
- 对于处在子网化网络**外部**的邻居 → 只发送一条聚合后的网络级条目
- 必须抑制那些能被网络级路由涵盖的主机路由

### 9.3 默认路由（0.0.0.0）

当路由表没有包含所有目的网络时，使用 0.0.0.0 作为「兜底」路由。它的处理方式与其他路由完全相同，但系统管理员**必须确保默认路由不会传播到超出预期的范围**。

## 十、协议的安全性与局限性

### 10.1 无安全机制

RFC 1058 版本的 RIP **没有任何认证机制**。「must be zero」字段的严格校验只是格式检查，不是安全控制。任何能发送 UDP 数据报到端口 520 的主机都可以向 RIP 路由器注入路由信息。

**建议的缓解措施**（可选实现）：
- **邻居列表**：只接受来自明确配置的邻居的响应
- **路由过滤**：按接口配置允许/禁止的目的地列表，入向过滤接受的路由，出向过滤通告的路由

### 10.2 固定度量值的局限

RIP 使用的是管理员**静态配置**的链路代价，默认每跳为 1。它**不适合**需要根据实时参数（如测量的延迟、可靠性、负载）来选择路由的场景。动态变化的度量值可能引入协议设计上无法处理的振荡和不稳定。

### 10.3 四大核心局限总结

| 局限 | 说明 |
|------|------|
| **15 跳网络直径** | 超过此规模，协议设计上不适用 |
| **计数到无穷** | 路由环路时带宽或时间开销大 |
| **固定度量值** | 不支持基于实时参数的动态选路 |
| **仅用于 AS 内部** | 是 IGP，不包括跨 AS 路由的功能 |

## 十二、概念地图

```
距离向量路由协议
    │
    ├── 核心算法：Bellman-Ford 方程
    │   ├── 增量更新（不每次全局重算）
    │   └── 「来自当前下一跳的更新必须接受」
    │
    ├── 定时器体系
    │   ├── 30 秒定期更新（加随机抖动防止同步）
    │   ├── 180 秒路由超时
    │   └── 120 秒垃圾回收
    │
    ├── 防环机制
    │   ├── 水平分割（不给来源通告可达性）
    │   ├── 毒性反转（故意发 metric=16）
    │   ├── 触发更新（坏消息即时传播）
    │   └── 无穷大 = 16（限制计数上限）
    │
    ├── 消息格式
    │   ├── UDP 520 端口
    │   ├── 最大 512 字节 / 25 条目
    │   └── 网络字节序
    │
    └── 适用场景
        ├── 中小规模 AS 内部
        ├── 网络直径 ≤ 15 跳
        └── 不适合需要动态度量的场景
```

## 十三、与其他协议的关系

| 协议 | 类型 | 算法 | 度量值 | 收敛速度 | 适用规模 |
|------|------|------|--------|----------|----------|
| **RIP** | IGP | 距离向量 | 跳数（最大 15） | 慢（分钟级） | 小 |
| **RIPv2** | IGP | 距离向量 | 跳数（最大 15） | 慢（分钟级） | 小 |
| **OSPF** | IGP | 链路状态 | 开销（带宽） | 快（秒级） | 中~大 |
| **EIGRP** | IGP | 混合（DUAL） | 复合度量 | 快 | 中~大 |
| **BGP** | EGP | 路径向量 | 多种属性 | 慢 | 全球互联网 |

RIP 在历史上的重要性不在于它有多强，而在于：它是最早被广泛实现的动态路由协议，它的设计思想和暴露出的问题，直接推动了后续协议（OSPF、EIGRP、BGP）的设计。理解 RIP，是理解所有路由协议的起点。
